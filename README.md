# Proof-of-Place

**From vague complaints to maintenance-ready tickets.**

Proof-of-Place is an AI-assisted maintenance intake layer. A person reports a problem in ordinary
words, optionally with a photo; **Gemma 4** interprets the evidence, suggests a category, extracts
what is known, points out what is *missing*, and asks a few targeted follow-up questions. The result
is a structured, editable, exportable maintenance ticket — reviewed and approved by a human before
anything leaves the browser.

It is deliberately **not** another photo-upload form and **not** an image caption generator. The
value is the transformation:

```
Unstructured complaint → targeted follow-up questions → maintenance-ready ticket
```

---

## Quick start

Requirements: Node.js 18+ (developed on Node 24).

```bash
npm install
cp .env.example .env      # then edit .env and add your GEMINI_API_KEY
npm run dev
```

- Web app: <http://localhost:5173>
- API: <http://localhost:8787>

Verify the model connection before demoing (performs a **real** API call):

```bash
npm run health -w server
```

It prints `Result: VERIFIED against model "gemma-4-26b-a4b-it".` only after a genuine successful
response. Anything else prints the exact failure (missing key, rejected key, quota, model
unavailable, network).

## Configuration (`.env`)

| Variable | Default | Purpose |
| --- | --- | --- |
| `GEMINI_API_KEY` | *(empty)* | Google AI Studio key. Server-side only — never sent to the browser. |
| `GEMMA_MODEL` | `gemma-4-26b-a4b-it` | Gemma 4 multimodal model (text + image input). |
| `GEMMA_API_BASE` | `https://generativelanguage.googleapis.com/v1beta` | Override for a proxy/self-hosted endpoint. |
| `PORT` | `8787` | API port. |
| `DEMO_MODE` | `false` | Returns **clearly labelled sample data** with no model call. |

**Model switching is manual on purpose.** If `gemma-4-26b-a4b-it` returns a quota error, the app
does *not* silently switch models. Change `GEMMA_MODEL` yourself (e.g. to `gemma-4-31b-it`),
restart, and re-run `npm run health -w server`. Availability of a model depends on your key and
project quotas.

Get a key: <https://aistudio.google.com/apikey>

## How it works

```
Browser (React + Vite + TS, holds no secrets)
   │  POST /api/analyze   description, optional location/category/context, optional photo
   ▼
Express API (Node)  ── one Gemma 4 call ──►  generateContent (inline base64 image + prompt)
   │  response parsed, repaired, validated field-by-field against a fixed schema
   ▼
Screen 2: category · summary · observed-from-photo · user-reported · missing info ·
          ≤3 follow-up questions  (each labelled AI or User)
   │  user answers
   ▼
/api/ticket → DETERMINISTIC composer (validated analysis + original input + answers)
   │          no second model call
   ▼
Screen 3: editable ticket → Approve → Copy / Download Markdown
```

### Endpoints

| Method | Path | Notes |
| --- | --- | --- |
| `GET` | `/api/health` | Real connectivity/auth probe; reports `ok`, `model`, `mode`, message. |
| `POST` | `/api/analyze` | Multipart. Fields `description`, `location`, `category`, `context`, `image`. |
| `POST` | `/api/ticket` | JSON `{ analysis, input, answers }` → composed ticket (pure function). |

### Validation and failure handling

- Uploads limited to **JPEG/PNG/WebP, 6 MB**; images are downscaled in the browser to ≤1024 px.
- Model output is never trusted: JSON is extracted (fence-stripped, brace-repaired), then every
  field is coerced, deduplicated and length-capped; the category must match a fixed enum.
- One corrective retry if the model replies with non-JSON prose.
- Errors map to actionable messages: `auth` (rejected key), `quota` (429), `not_found`
  (model unavailable to this key), `timeout`, `network`, `bad_input`.

### Honesty rules baked into the product

- The UI never claims a ticket was submitted, acknowledged or resolved — only *"Prepared for
  submission"*, with an explicit note that no system was contacted.
- AI output is labelled **AI**, user input labelled **User**; hypotheses are never presented as
  facts and urgency flags are *"for human review"*, never a safety verdict.
- `DEMO_MODE` responses are watermarked **"Sample data — not generated by the model"** everywhere
  they appear.
- Urgent hazards (exposed wiring, flooding, gas) carry a precautionary banner pointing to the
  institution's emergency channel rather than to more questions.

## Privacy

- Credentials live only in `.env` (git-ignored) and are read by the server process.
- Photos and descriptions are held in memory for the length of one request and are **not stored**
  anywhere by this application; no database, no accounts, no logging of complaint content.
- What you submit is transmitted to the configured model provider (Google AI Studio / Gemini API)
  for analysis. The UI states this to users.
- Do not include passwords, access tokens, faces or unnecessary personal information.

## Development commands

```bash
npm run dev               # API :8787 + web :5173 together
npm run build             # type-check + production build of the web app
npm run start             # API only
npm run health -w server  # real Gemma 4 connectivity check
```

## Scope

MVP only: no database, no authentication, no staff dashboard, and **no direct integration with any
college maintenance portal**. Export (copy / Markdown download) is the hand-off mechanism.
